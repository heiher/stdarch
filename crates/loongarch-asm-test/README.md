# LoongArch LSX/LASX assembly test

Checks that each LoongArch64 LSX/LASX intrinsic in `core_arch` compiles to the
instruction it is named after, and prints the generated assembly so you can see it.

```sh
rustup target add loongarch64-unknown-linux-gnu   # needed once on other hosts

cargo test -r -p loongarch-asm-test                     # every intrinsic
cargo test -r -p loongarch-asm-test -- vadd xvpermi     # only names containing a filter
cargo test -r -p loongarch-asm-test -- --quiet          # summary only
cargo test -r -p loongarch-asm-test -- --list           # list intrinsics + signatures
cargo test -r -p loongarch-asm-test -- --llvm-ir        # LLVM IR instead of asm, plus one .ll per intrinsic
cargo test -r -p loongarch-asm-test -- --llvm-ir=DIR    # same, writing the .ll files to DIR
```

On non-LoongArch hosts the code is cross-compiled. Nothing runs, so no emulator or
cross linker is needed, only the `rust-std` component for the target. If that
component is missing, the test prints a notice and is skipped.

## How it works

1. **Intrinsic list.** The intrinsics and their Rust signatures come from
   `crates/stdarch-gen-loongarch/{lsx,lasx}.spec`, using the same rules as the
   generator. This covers both the LLVM-intrinsic and the portable
   (`intrinsics::simd`) implementations.
2. **Wrappers.** One `#[no_mangle]` wrapper is generated per intrinsic, in
   `target/tmp/loongarch-asm-test/src/lib.rs`:

   ```rust
   #[unsafe(no_mangle)]
   #[target_feature(enable = "lsx")]
   pub unsafe fn lsx_vadd_b() {
       unsafe {
           let a: arch::m128i;
           let b: arch::m128i;
           asm!("# in: a={0}, b={1}", out(vreg) a, out(vreg) b, options(nomem, nostack, preserves_flags));
           let r: arch::m128i = arch::lsx_vadd_b(a, b);
           asm!("# out: {0}", in(vreg) r, options(nomem, nostack, preserves_flags));
       }
   }
   ```

   Operands go in and out through empty `asm!` blocks (`vreg`/`xreg`/`reg`), so:
   - the optimizer can't see the values, which rules out constant folding;
   - there is no call-ABI noise: no `vld`/`vst` for by-reference vector arguments,
     no sign extension of return values, and no scalar loads replacing an extract.

   Immediates are chosen to avoid values that LLVM would rewrite into other
   instructions (see `IMM_OVERRIDES` and `default_imm` in `src/lib.rs`).
3. **Build.** The wrappers are built for `loongarch64-unknown-linux-gnu` with
   `--emit asm` and `-Zmerge-functions=disabled`. Each function body is then
   extracted, with directives and `#APP` markers removed.
4. **Check.** Each body is compared with `Intrinsic::expect()`:
   - `ok`: only the named instruction (`lsx_vadd_b` → `vadd.b`).
   - `ok, equivalent instruction`: a single instruction that computes the same
     result, e.g. `vpickev.d` vs `vpackev.d`, or `vslei` becoming `vslti imm+1`.
   - `EXTRA INSTRUCTIONS` or `MISSING INSTRUCTION`: the test fails.

## LLVM IR for standalone LLVM work

With `--llvm-ir`, the test writes one standalone module per intrinsic to
`target/tmp/loongarch-asm-test/llvm-ir/<name>.ll`, or to `DIR`, and prints these
modules instead of the assembly. The checks still run. You can feed these files
straight to `llc` to work on instruction selection and optimization in LLVM itself:

```sh
llc -O3 < target/tmp/loongarch-asm-test/llvm-ir/lsx_vbitclr_b.ll
```

Each file contains rustc's *optimized* IR for the wrapper, which is what reaches
the LoongArch backend. It is rewritten in the style of an LLVM codegen test:

- The operands from the input `asm!` block become function parameters, named
  after the Rust parameters.
- The value passed to the output `asm!` block is returned.
- Unnamed values are renamed (`%0` → `%v0`), and metadata and call-site attributes
  are removed.
- Only the declarations the function calls are kept, plus an attribute group with
  `target-cpu` and the de-duplicated `target-features`.
- The header has the Rust signature, the call being tested, the expected
  instruction and the assembly rustc produced, for comparison.

```llvm
; pub fn lsx_vbitclr_b(a: m128i, b: m128i) -> m128i
; Rust test: lsx_vbitclr_b(a, b) => vbitclr.b
;
; Generated by crates/loongarch-asm-test from rustc's optimized LLVM IR.
; RUN: llc -O3 < %s
;
; rustc output:
;   vrepli.b        $vr2, 1
;   vsll.b          $vr1, $vr2, $vr1
;   vandn.v         $vr0, $vr1, $vr0
;   ret

target datalayout = "e-m:e-p:64:64-i64:64-i128:128-n32:64-S128"
target triple = "loongarch64-unknown-linux-gnu"

define <2 x i64> @lsx_vbitclr_b(<2 x i64> %a, <2 x i64> %b) #0 {
start:
  %v3 = bitcast <2 x i64> %b to <16 x i8>
  %_8.i = and <16 x i8> %v3, splat (i8 7)
  %_3.i = shl nuw <16 x i8> splat (i8 1), %_8.i
  %v4 = bitcast <16 x i8> %_3.i to <2 x i64>
  %v5 = xor <2 x i64> %v4, splat (i64 -1)
  %v6 = and <2 x i64> %a, %v5
  ret <2 x i64> %v6
}

attributes #0 = { nounwind "target-cpu"="generic" "target-features"="+f,+d,+lsx,+relax" }
```

The vector parameters and return values travel in `$vr`/`$xr` registers under
LLVM's calling convention, so `llc` output matches rustc's. Scalar `i32`
results are returned without `signext`, matching the `asm!` sink.

Example output (assembly mode):

```
// lsx_vsub_b(a, b) => vsub.b [ok]
lsx_vsub_b:
    # in: a=$vr0, b=$vr1
    vsub.b          $vr0, $vr0, $vr1
    # out: $vr0
    ret
```
